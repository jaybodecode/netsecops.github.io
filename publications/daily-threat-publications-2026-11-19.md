- [N0N Extortion Group Claims Breach of 830M Expedia Loyalty Records](https://cyber.netsecops.io/articles/n0n-extortion-group-claims-expedia-data-breach-without-proof/) (high)
  The data extortion group N0N has listed Expedia Group on its dark web leak site, claiming to have exfiltrated 830 million records from the company's loyalty program. The group alleges the data includes customer emails, loyalty IDs, and booking values. However, as of November 9, 2026, N0N has not provided any proof to substantiate its claims. Expedia Group has not issued a public statement or filed a material incident report regarding the alleged data exposure. Security analysts advise caution, as such claims are sometimes exaggerated or fabricated.
- [N-able Confirms Server Breach Caused Email Security Service Outage](https://cyber.netsecops.io/articles/n-able-cloud-server-breach-disrupts-global-email-security-services/) (high)
  N-able has confirmed a security incident involving unauthorized access to a server supporting its Mail Assure and SpamExperts hosted cloud platforms. The breach, which began on November 16, 2026, led to a multi-day service disruption across the Americas, Europe, and APAC. As a precaution, N-able disabled management interfaces, APIs, and quarantine access. While core email filtering remained operational, administrators were unable to manage the services. An investigation is ongoing to determine the attack vector and full impact, though N-able has stated there is currently no evidence of customer data compromise. This incident is reportedly separate from a recent vulnerability in its N-central RMM product.
- [Visa Confirms Third-Party Breach by 'n0n' Gang; Premium Data Leaked](https://cyber.netsecops.io/articles/visa-confirms-third-party-breach-leaking-premium-customer-data/) (high)
  Visa has confirmed a data breach originating from a third-party vendor in the Asia-Pacific region that managed loyalty programs. The incident was claimed by the 'n0n' ransomware group, which leaked data on November 19, 2026, allegedly affecting over 6,000 premium Visa cardholders. Visa asserts that its own systems were not compromised and no payment card numbers were exposed. The leaked data includes information about customer engagement with luxury dining programs, such as campaign names and event details. Security experts warn this information could be used for sophisticated phishing attacks against high-net-worth individuals.
- [UCHealth Breach Affects 129,000 Patients, Triggers Class-Action Lawsuit](https://cyber.netsecops.io/articles/uchealth-data-breach-affects-129000-patients-triggers-lawsuit/) (high)
  Colorado-based UCHealth is notifying approximately 129,000 individuals that their personal and health information was exposed in a data breach discovered in July 2026. The incident involved unauthorized access to two employee Microsoft cloud accounts. Exposed data could include names, Social Security numbers, and health information. Following the disclosure, a class-action lawsuit was filed against UCHealth on November 18, 2026, alleging failure to protect patient data and criticizing the nearly four-month delay in notifying victims, which may violate HIPAA's 60-day notification rule.
- [Microsoft's 'agent-framework' PyPI Package Hijacked to Steal Credentials](https://cyber.netsecops.io/articles/microsoft-agent-framework-pypi-package-hijacked-to-steal-credentials/) (critical)
  A supply chain attack compromised two versions of Microsoft's official 'agent-framework' package on the Python Package Index (PyPI). On November 17, 2026, malicious versions 1.26.1 and 1.26.2 were published, containing a credential-stealing payload. The malware, affecting a package with ~190,000 monthly downloads, was designed to harvest secrets from developer environments and CI/CD pipelines, including credentials for Azure, AWS, GitHub, Docker, and npm. The malicious code executed automatically via a .pth startup hook, making it highly evasive. The compromised packages have been removed, but developers are urged to rotate all potentially exposed secrets.
- [Leaked Cloud Keys on Docker Hub Exploited in Under 8 Seconds, Study Finds](https://cyber.netsecops.io/articles/leaked-cloud-keys-on-docker-hub-exploited-in-under-8-seconds/) (critical)
  Research from Stony Brook University reveals a critical software supply chain risk: cloud credentials and API keys accidentally embedded in public Docker Hub images are being discovered and exploited by automated bots in as little as 7.86 seconds. The study, which planted honeypot keys, found that all AWS keys were abused within 15 minutes, with a median compromise time of 51 seconds. The 'ContainerBots' use static analysis to extract secrets from image layers without running the containers, bypassing many runtime defenses. The findings highlight the near-zero window developers have to remediate accidental secret exposure in public container registries.
- [Decade-Old 'nginx2root' Flaw (CVE-2026-123007) Allows RCE on NGINX Servers](https://cyber.netsecops.io/articles/decade-old-nginx2root-flaw-cve-2026-123007-allows-rce-on-nginx-servers/) (high)
  A critical, decade-old remote code execution (RCE) vulnerability in NGINX's HTTP/2 implementation has been disclosed. Dubbed 'nginx2root' and tracked as CVE-2026-123007, the flaw allows an unauthenticated attacker to execute code on vulnerable servers. It affects all open-source NGINX versions from 1.9.5 (released in 2015) to 1.31.8. While the exploit grants code execution as the NGINX worker process, it can be chained with a kernel privilege escalation to gain full root access. F5 has released patched versions. Exploitation is considered difficult, requiring large amounts of traffic, and no in-the-wild attacks have been observed yet.
- [Over Half of Mobile Banking Apps Have Critical Flaws, Study Finds](https://cyber.netsecops.io/articles/widespread-vulnerabilities-found-in-over-half-of-mobile-banking-apps/) (high)
  A security analysis of 2,686 mobile banking apps from 487 banks across 64 countries found that over 51% contain high or critical severity vulnerabilities. The study, by Ostorlab, identified significant risks including hardcoded credentials in 20% of apps, bypassable biometric authentication in 35% of Android apps, and the use of outdated, vulnerable components in 41% of apps. The research highlights a slow adoption of modern security practices like passkeys and underscores the systemic risk to global financial customers from inadequately secured mobile applications.
